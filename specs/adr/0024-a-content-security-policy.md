# ADR-0024: A content security policy that admits only this origin

- **Status:** Accepted (2026-09-13)

## Context
An audit of the UI found that the application sent **no resource CSP**. The only CSP header it emitted
was the one Blazor Web Apps add on component endpoints — `Content-Security-Policy: frame-ancestors
'self'` — which restricts framing and nothing else. With no `default-src`, `script-src`, `style-src`,
`font-src`, `img-src` or `connect-src`, every resource type was unrestricted: one injected script tag,
one `@import`, one `fetch` to anywhere would load unchallenged.

The audit also found the application is in an unusually strong position to be strict. It references
**no external resource of any kind**: scripts, stylesheets, fonts, images and links are all
same-origin, both font families are self-hosted, and there is no inline `<script>`, no `<style>`
block, no inline event handler and no `eval`/`Function`/`innerHTML` in its own JavaScript. Only two
things stood between it and a `'self'`-only policy: **one inline `style=` attribute** on the builder
canvas, and **`data:` image URIs** generated by Tailwind for the native form controls.

## Decision
- **The policy admits this origin and nothing else**, with two named exceptions:
  `default-src 'self'`, `script-src 'self'`, `style-src 'self'`, `font-src 'self'`,
  `connect-src 'self'`, `img-src 'self' data:`, `object-src 'none'`, `base-uri 'self'`,
  `form-action 'self'`, `frame-ancestors 'none'`, `upgrade-insecure-requests`.
- **It is a response header, not a `<meta>` tag.** `frame-ancestors` is ignored in a meta tag, and
  only a header can carry violation reporting.
- **`connect-src 'self'`, never the `ws:`/`wss:` schemes.** The guidance for Blazor offers those
  schemes because the circuit is a WebSocket, but a scheme source permits a socket to *any* host. If a
  browser ever refuses the same-origin socket under `'self'`, the answer is to name the origin.
- **No nonce and no `unsafe-inline`.** A nonce exists to admit inline script that would otherwise be
  blocked, and there is none: the rendered HTML has no inline script and no import map. Adding a nonce
  would be machinery with no purpose and a place for `unsafe-inline` to creep back in. The one inline
  style was moved into a stylesheet class instead.
- **`img-src data:` is kept.** Tailwind draws the native select and checkbox decorations with `data:`
  URIs. A `data:` image cannot make a request, so admitting it costs nothing; unpicking generated
  output would be churn for no security gain.
- **The framework's own `frame-ancestors` is configured to `'none'`, not fought.** Two CSP headers are
  enforced together, as an intersection, so leaving the framework's `'self'` in place would be a subtle
  way to be wrong.
- **Companion headers ride along in the same middleware**: `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer` (the order links carry access tokens in their query strings), and a
  `Permissions-Policy` that grants no feature.
- **HTTPS redirection joins HSTS in production**, where it previously stopped short of sending a
  browser to HTTPS the first time.
- **The policy was delivered report-only first.** Its failure mode is not an error page — it is a page
  that renders perfectly and never becomes interactive, because the circuit's socket was refused, and
  no status code shows that. It was enforced only after the browser suite proved the circuit survives.

## Consequences
- **A security control now has a test that can fail.** A browser test fails on any CSP violation the
  browser reports, across a full load, an interactive circuit and a catalogue request. It was proved
  non-vacuous by deliberately breaking the policy (`script-src 'none'`) and watching the test fail.
- **Two source-level rules keep it honest**: a component may not carry an inline style attribute or an
  inline script block, and may not load a resource from another origin. Together with the existing
  third-party-request assertion, the policy cannot be quietly widened without a test going red.
- **The application is now harder to extend carelessly.** A future feature that wants a CDN, a font
  host or a third-party script will not work until the policy is changed on purpose. That friction is
  the point.
- **`frame-ancestors 'none'` is stricter than the framework's default.** An application that is never
  framed refuses to be framed, including by itself.
- **The framework still sends `X-Frame-Options: SAMEORIGIN` on component responses**, for browsers
  that predate CSP. `frame-ancestors 'none'` is the directive that decides in every current browser,
  and the legacy header is left as the framework writes it: adding a second value would mean two
  conflicting `X-Frame-Options` headers, which is a worse outcome than a header only very old browsers
  read.
- **A page that breaks under the policy breaks quietly.** Anyone changing the markup should expect the
  CSP violation test to be the thing that tells them.

## Alternatives rejected
- **`<meta http-equiv="Content-Security-Policy">`.** Cannot express `frame-ancestors` and cannot carry
  a report destination.
- **Microsoft's sample policy verbatim** (`connect-src 'self' http: ws: wss:`, `img-src data: https:`,
  `wasm-unsafe-eval`). It is a starting point for apps that reach out; this one does not, and each of
  those sources would widen it. `wasm-unsafe-eval` is not needed because the app is Interactive Server,
  with no WebAssembly.
- **A nonce-based policy.** Nothing inline needs admitting.
- **`style-src 'unsafe-inline'` to keep the one inline style.** That single allowance would let any
  injected style run, which is most of what the policy is for.
- **Report-only permanently.** It observes violations and prevents nothing; it is a rollout step, not
  a destination.
- **Subresource Integrity, Trusted Types and a report collector.** Defensible follow-ons, none needed
  to reach the stated goal.
