# Plan — enforce a Content Security Policy

## Problem Statement

The application sends **no resource CSP**. The only CSP header it emits is the one Blazor Web Apps add
by default on component endpoints:

```
Content-Security-Policy: frame-ancestors 'self'
```

That restricts framing and nothing else. There is no `default-src`, `script-src`, `style-src`,
`font-src`, `img-src` or `connect-src`, so **every resource type is unrestricted**: one injected
script tag, one `@import`, one `fetch` to anywhere would load without the browser objecting.

The audit that precedes this plan established that the UI is in an unusually strong starting
position: **zero external resources** of any kind — scripts, stylesheets, fonts, images and links are
all same-origin, fonts are self-hosted, there is no inline `<script>`, no `<style>` block, no inline
event handler, and no `eval`/`Function`/`innerHTML` in the application's own JavaScript. A strict
`'self'`-only policy is therefore achievable with **exactly two exceptions**:

1. **One inline `style=` attribute** — the canvas background in the builder (`SlotCanvas`). An inline
   style attribute cannot be nonced or hashed in practice, so it would force `style-src
   'unsafe-inline'`, which is the single biggest weakness a CSP can have.
2. **`data:` image URIs inside CSS** — five, generated by Tailwind for the native select and checkbox
   decorations. These need `img-src data:`.

The goal is an enforcing policy that permits **nothing external**, with the smallest possible set of
exceptions, each one written down and justified.

## Solution

Add a security-headers middleware that emits a strict CSP on **every** response, tighten the
framework's own `frame-ancestors` to match, remove the one inline style so `style-src 'self'` can be
enforced, and ship the whole thing as `Content-Security-Policy-Report-Only` first so any violation is
observed rather than guessed at.

**Target policy**

```
default-src 'self';
base-uri 'self';
object-src 'none';
frame-ancestors 'none';
form-action 'self';
script-src 'self';
style-src 'self';
img-src 'self' data:;
font-src 'self';
connect-src 'self';
upgrade-insecure-requests;
```

Two things about that policy are deliberate:

- **`connect-src 'self'` rather than Microsoft's `'self' ws: wss:`.** The Blazor circuit is a
  same-origin WebSocket, and `ws:`/`wss:` as written would permit a socket to *any* host, which is the
  opposite of what this change is for. If a browser refuses the same-origin socket under `'self'`,
  the fallback is the specific origin (`wss://host`), not the scheme — recorded in the commits below.
- **No `wasm-unsafe-eval`, and no nonce or hash.** The app is Interactive Server only (no WASM), and
  the rendered HTML confirmed there is no `<ImportMap />` inline script and no inline `<script>` at
  all. Nothing needs to be admitted by hash or nonce today; if that changes, the framework's inline
  import map would need one, and the Report-Only phase is where that would show up.

**Why a header and not a `<meta>` tag:** `frame-ancestors` is ignored in a meta tag, the framework
already sets a header, and only a header can carry violation reporting.

**How the two headers coexist:** the framework adds `frame-ancestors 'self'` on component endpoints
only (verified — static files and the framework script carry no CSP). Multiple CSP headers are
enforced independently, which is an intersection, so the two must not disagree. The framework's value
is set to `'none'` through the documented `ContentSecurityFrameAncestorsPolicy` option so both headers
say the same thing, and the middleware carries the rest.

## Commits

Shorthand:

- `BUILD` → `dotnet build CoreRentalNet.sln`
- `NONBROWSER` → `dotnet test CoreRentalNet.sln --filter "FullyQualifiedName!~CoreRentalNet.E2E"`
- `BROWSER` → `dotnet test tests/CoreRentalNet.E2E`

### Phase 0 — baseline

```
0. Record the baseline: NONBROWSER and BROWSER green, and the audit facts (no external resource, one
   inline style, the framework's frame-ancestors) → verify: NONBROWSER && BROWSER
```

### Phase 1 — remove the two blockers

```
1. Give the builder canvas its own class for the dotted background, in the stylesheet source, and
   rebuild the stylesheet. The colour is the current one, so the page does not change. → verify: BUILD && BROWSER

2. Drop the inline style attribute from the canvas markup, using the class from commit 1. After this,
   no component carries an inline style and style-src 'self' becomes possible. → verify: BROWSER

3. Add a source-level architecture rule: no .razor file may contain an inline style attribute or an
   inline script block, so the two things a strict style-src forbids cannot come back. Assert the
   scan is non-vacuous. → verify: NONBROWSER

4. Tighten the framework's own frame-ancestors from 'self' to 'none' using the documented option on
   the interactive server render mode. → verify: BROWSER
```

### Phase 2 — the policy, in Report-Only

```
5. Add a security-headers middleware that sets Content-Security-Policy-Report-Only to the target
   policy on every response, ahead of the static-file middleware so assets are covered too. → verify: BUILD

6. Add a browser test that fails on a CSP violation: it reads the page's console for a
   Content-Security-Policy message while a full page load, an interactive circuit and a category
   switch happen. This is the test that turns "report-only" into evidence. → verify: BROWSER

7. Run the whole browser suite and the opt-in real-tenant run with report-only in place, and record
   every violation. Fix what is fixable; for anything that is not, add the narrowest source that
   admits it and write down why. The two known ones are the data: images and the circuit socket. → verify: BROWSER
```

### Phase 3 — enforce

```
8. Flip the header from Content-Security-Policy-Report-Only to Content-Security-Policy, unchanged. → verify: BROWSER

9. Assert the circuit still becomes interactive under enforcement (the existing circuit wait is the
   proof; a broken policy renders the page and never connects). → verify: BROWSER

10. Add the companion headers: nosniff, a referrer policy and a permissions policy. Each is its own
    line, so one can be reverted without touching the CSP. → verify: BROWSER

11. Enable HTTPS redirection in production beside the existing HSTS, gated so development and the
    test hosts are untouched. → verify: BUILD && BROWSER
```

### Phase 4 — lock it in

```
12. Add a browser test that asserts the delivered header: it is present, it is enforcing, and it
    contains neither unsafe-inline nor unsafe-eval. → verify: BROWSER

13. Add an architecture rule that no component references an absolute http(s) resource, beside the
    existing third-party-request assertion, so the policy cannot be quietly widened. → verify: NONBROWSER

14. Record the decision in an ADR: the policy, the two exceptions and their justification, why
    connect-src is 'self' rather than ws:, and the report-only rollout. Update the verification
    document with the header as delivered. → verify: BUILD
```

## Decision Document

**Modules built or modified**

- **A security-headers middleware** in the host's infrastructure, beside the existing draft-token
  middleware. It owns the policy and the companion headers in one place; it reads no configuration and
  applies to every response.
- **The builder canvas stylesheet rule** that replaces the inline style.
- **The composition root**, for the middleware registration and the framework's frame-ancestors
  option.

**Interfaces changed**

- None. No public type, route, view model or database shape changes. The middleware is the only new
  type, and it is internal to the host.

**Technical decisions**

- **The CSP is a response header, not a meta tag** — `frame-ancestors` is ignored in a meta tag and
  reporting needs a header.
- **`connect-src 'self'`, with explicit origins as the fallback** — never the `ws:` scheme, which would
  permit an external socket and defeat the purpose.
- **`img-src data:` is kept** because Tailwind generates those URIs for native form controls. Replacing
  them means unpicking generated output for no security gain: a `data:` image cannot make a request.
- **No nonce.** A nonce exists to admit inline script that would otherwise be blocked. There is none,
  so a nonce would add per-response machinery and a place for `unsafe-inline` to creep in.
- **No `unsafe-inline` anywhere.** This is the whole point of commit 2.
- **The framework's frame-ancestors is configured, not fought.** Two headers intersect, so leaving
  them inconsistent would be a subtle way to be wrong.
- **Report-Only first.** The failure mode of a wrong CSP is a page that renders and never becomes
  interactive — invisible to a status-code test, and the reason the circuit assertion exists.

**Out-of-scope decisions**

- Subresource Integrity, Trusted Types, and a violation-report collector. Each is a defensible
  follow-on; none is needed to meet the stated goal.

## Testing Decisions

**What makes a good test here:** the policy is a delivered header and a browser behaviour, so the tests
assert the header the app sends and the behaviour the browser has under it. Nothing asserts how the
policy string is built.

**Coverage that already protects this work**

- **HermeticityTests** already fails if any request leaves the origin, which is the same property the
  policy enforces, measured from the browser's side.
- **CanvasLayoutTests / the builder tests** render the canvas whose inline style is being removed.
- The **circuit wait** used by every interactive test is the signal that the Blazor connection
  survived; it fails loudly if CSP blocks the socket.
- The **opt-in real-tenant run** exercises the same pages with identity on.

**New tests proposed**

- A browser test that fails on a CSP violation message in the console, across a full load, an
  interactive circuit and a category switch.
- A browser test that asserts the delivered header is enforcing and free of `unsafe-inline` and
  `unsafe-eval`.
- A source-level architecture rule for inline style attributes and inline script blocks.
- A source-level architecture rule for absolute http(s) references in components.

**Verification**

- Every commit: `BUILD`, then the suite the change touches.
- No `test-matrix.md` expectation changes. A new matrix row covers the header itself.

## Out of Scope

- Subresource Integrity, Trusted Types, reporting endpoints and a violation collector.
- Changing any third-party dependency, or vendoring anything new: nothing external is referenced, so
  there is nothing to vendor.
- The identity provider's own pages, which are on its origin and governed by its headers, not this
  policy.
- Non-security headers (caching, CORS), which are already stated where they matter.

## Further Notes

- The audit is what makes this cheap: because there are no external resources, this is an *enabling*
  change rather than a migration. The only code change is one inline style becoming a class.
- The failure mode to watch is **the circuit**: CSP blocks the WebSocket and the page silently stops
  responding. That is why report-only runs first and why the enforcement commit asserts interactivity
  rather than a status code.
- If a future feature wants an external resource, the CSP is the thing that will force the
  conversation — which is exactly what it is for.
