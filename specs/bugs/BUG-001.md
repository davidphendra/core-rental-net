# BUG-001 — Expired Auth0 access token used as if valid

## Symptom

A signed-in customer whose Auth0 access token had expired could still open the builder. The suggestion run
then failed at the catalogue: the agent presented the expired token to the catalogue's MCP server, which
refused it, so the MCP tools could not be reached and the run ended `unavailable`. The sign-in cookie
(`ExpireTimeSpan = 14 days`) kept the session looking valid long after the token had died.

## Root cause

- `IdentityRegistrationExtentions.RegisterProvider` configured `.WithAccessToken(o => o.Audience = …)` but
  never set `UseRefreshTokens`. The Auth0 SDK gates its own expiry check and refresh on that flag, and the
  flag is also what adds `offline_access` to the authorize request — so no refresh token was ever requested,
  and the SDK's own `OnValidatePrincipal` refresh returned immediately.
- The app read the token with its own `SessionTokenExtensions.GetAccessTokenAsync`
  (`HttpContext.GetTokenAsync("access_token")`): a raw ticket read with no expiry check and no refresh.
  `TokenHandler` did the same.
- Consequence: a valid cookie meant "signed in", and an expired access token was forwarded as
  `x-client-mcp-catalog-access-token`.

## Fix

None of the expiry handling is implemented by the application; the Auth0 SDK already does both halves.

1. `UseRefreshTokens = true` and `AccessTokenExpirationLeeway = TimeSpan.FromMinutes(2)` on
   `.WithAccessToken(...)`, with `OnMissingRefreshToken` and `OnAccessTokenRefreshFailed` ending the session
   and re-challenging.
2. `SessionTokenExtensions` deleted; the token is read through
   `HttpContext.GetAccessTokenAsync(new AccessTokenRequest())` in `BuilderController` and `TokenHandler`.
   A `null` answer means the session can no longer produce a token.
3. `BuilderController` refuses with **401** (was 403) and a "session has expired" detail.
4. New `SessionController : ControllerBase` reports the SDK's answer at `GET /api/account/session`
   (`canRunSuggestion`, `sessionExpiresAt`); the panel maps a 401 / `canRunSuggestion: false` to a
   "sign in again" notice.

## Residual

- Auth0 application prerequisite: **Allow Offline Access** on the API, or the SDK fires
  `OnMissingRefreshToken` and the customer is asked to sign in again.
- An end-to-end flow that exercises the refresh against the local provider is not yet written. The local
  provider now issues and honours refresh tokens (lifetime configurable with `ACCESS_TOKEN_TTL_SECONDS`),
  but the browser suite cannot run until `CoreRentalNet.E2E.LocalAgent` exists.
